# M20-S5: pointer-free typed-address checks

## Decision and scope

This is a default-off runtime candidate under RFC-306, separate from ordinary
return-frame specialization and the fast-cgo entry. It has no measured speed
claim yet. Required correctness, regression, and G6 acceptance evidence must
be completed before promotion.

The exact predicate admits only an existing typed-address marker whose Go
element type contains no pointers. It reads type metadata before the existing
address classifier. Unknown provenance, unsafe pointer types, pointer-bearing
elements, and non-boolean marker kinds follow the unchanged checker.

## Why the transformation preserves the check

The boolean-marker branch of `cgoCheckPointer` already checks the original
pointed-to Go type. `cgoCheckArg` returns immediately when that type has no
pointers. The earlier nil and foreign-address checks also return without
effects. Moving this proven no-op before address classification preserves all
of those outcomes. The predicate does not read the supplied address.

A pointer-free field in a pointer-bearing object is a useful boundary test.
Passing its original typed address confines the check to the field. Saving an
unsafe pointer loses that provenance, so the existing full allocation scan
must still find and reject the adjacent unpinned pointer. Pinning the nested
allocation makes that saved-pointer case legal again.

This proof does not authorize changes to callbacks, exported results, pinning,
escape analysis, scheduler transitions, or `unsafe.Pointer` provenance.

## Test-first protocol

The first commit contained the test cases, a false-returning helper scaffold,
and a test-only export. Before any production change, a separate test-only
correction changed an interface rejection expectation to the actual upstream
`unpinned Go interface` diagnostic. No input or rejection assertion was removed.

At test-only commit `a874a950acb0f05e67ce1dcbcad358bfe1bf1b94`,
[CI run 43827979866, job 133166219731](https://github.com/gosuda/LoGOs/actions/runs/43827979866/job/133166219731)
recorded the intended RED at 08:22:02 UTC on 2026-11-16. Exactly eight eligible
classifier cases failed with `pointer-free address eligibility = false, want
true (logoscgoopt=true)`: scalar, named scalar, typed nil scalar, pointer-free
array, empty struct, pointer-free field, named boolean marker, and false
boolean marker. The negative classifier controls, pointer-boundary and
container checks, and actual C fixture passed. The build, formatting, explicit
off/on vet checks, and inherited return-frame mutation controls also passed.
The full regression and benchmark jobs were correctly skipped.

The implementation replaces the scaffold after that observed RED. All seven
other test, fixture, export, and manifest blobs are frozen; their Git blob
hashes are in [the evidence record](M20-S5-evidence.jsonl). The first production
candidate adds the helper predicate and a three-line early-return hook. Its
new mutation probe reverses the pointer-free condition and requires the
pointer-bearing-value attack to report `cgo pointer check accepted an unpinned
nested pointer`, then restores the source and requires GREEN.

The production candidate's build, full off/on instrumented matrix, mutation
probe, sanitizer and stock-toolchain fixtures, full regression, and performance
gates are pending. Test-first RED is not evidence that those gates passed.

The attack suite covers named and nil pointers, arrays and structs with no
pointers, pointer-bearing fields and containers, unsafe pointers, marker kinds,
unknown interior pointers, pinned success after GC, actual C reads, and
deferred evaluation. Nested targets use allocations larger than the tiny
allocator to avoid accidental pin sharing. Tests also reject an out-of-line
predicate call in the runtime.

Required commands run the runtime family and actual cgo integration in normal,
race, and `cgocheck2` modes with the experiment off and on. A dedicated manifest
requires each named test to execute; enabled skips are failures. Full
`run.bash` remains a separate regression gate.

## Performance protocol

`BenchmarkCgoOptPointerFreeAddress` invokes one unmarked void C consumer of the
addressed bytes. The void wrapper isolates this candidate from result-frame
elision. Its unpinned neighboring pointer also prevents accidental replacement
with the arbitrary-pointer contract.

Baseline and candidate use identical source and fixed work with fast-cgo
disabled; only `logoscgoopt` changes. Preserve primary warmups and all measured
samples, ten fixed-count Go benchmark samples, separately collected profiles,
allocations and binary sizes. Reject noisy pairs before scoring. Repeat the
same work for integration and retain the 1.05 threshold.

A native C call or a typed-pointer comparison does not establish the lower
bound for this runtime contract. That evidence and hot-path admission must be
established separately. Until the record is complete, this remains an
unaccepted candidate with the default unchanged.
