middle dots, or that accepts every fact object as a package declaration.

## Actual producer and importer control

`TestCompileSIMDTaggedFuncFacts` uses the installed compiler to build real
`simd` export archives. It reads `__.LOGOS` with the existing `readFacts` helper,
which decodes the fact member, and imports the archive through the public
compiler type importer. The test requires exactly one known `0/0` assertion
record for each of `Float32sFromArch@simd0` and `Float32sFromArch@simd128`, verifies
the imported generic declaration, and checks that `ApplyFuncFacts` transfers
the masks to that exact object. It does not manufacture a tagged declaration
or synthesize its fact record.

The test builds archives for linux/amd64 with explicit `GOEXPERIMENT=none,simd`
and `CGO_ENABLED=0`. It does not execute target binaries. The CI acceptance
command must run this test without `-short` and require its named PASS event;
an unavailable compiler, a skip, or a missing event is not acceptance.

The source-level producer trace, established before execution, is:

1. `src/simd/tofrom_amd64.go` defines generic `Float32sFromArch` with type assertions.
2. `midway/rewrite.go` generates dependent declarations with `@simd%d` suffixes; `midway/midway.go` includes sizes 0 and 128 for amd64.
3. `midway/deepcopy.go` creates the tagged syntax names and functions.
4. `noder/irgen.go` rechecks the rewritten AST before calling `logosWriteCheckedFacts`.
5. `types2/const_assert_effects_logos.go` exports known generic assertion masks; `facts/write_assert.go` writes the exact tagged scope name.
6. `noder/unified.go` retains exported tagged declarations; `importer/ureader.go` inserts their names lazily.
7. `noder/logos_import.go` calls `ApplyFuncFacts`; the old package-name filter excludes the tagged declaration before matching its fact.

`logosWriteCheckedFacts` calls `facts.WriteChecked` unconditionally; assertion
fact writing is not gated by `base.Logos` or `base.LogosGoFacts`. The latter
controls the separate `EmitGoMutations` pass for Go packages. No claim here
depends on readonly inference producing a SIMD fact.

## Separate unresolved codec limitation

`facts.MethodObject("Box@simd128", receiver, "Read")` places the tag inside the
type name, yielding `Box@simd128.Read` for a value receiver. `facts.ValidObject`
splits at `@` first and rejects the remaining tag containing a dot. This is a
distinct source-level producer/codec inconsistency. This slice does not change
that wire grammar or claim a measured runtime failure for it.

The new readonly controls use the supported tagged root plus a method path,
such as `{Object: "Shelf@simd128", Path: "MRead"}`. The reachable-method control
uses a valid `hidden.As` record whose owner is reachable only through a tagged
root. Neither treats the unresolved tagged-receiver method spelling as a valid
encoded fact.
