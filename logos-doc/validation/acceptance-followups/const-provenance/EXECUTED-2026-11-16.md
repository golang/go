## Documentation consequence and limits

The source already implements the mechanisms described as planned in
M5-S1: `logosConstOrigin`, readonly aggregate descendants, the five known
unsafe derivation handlers, qualification-erasing boundary checks, and
the returned-alias check for proven-zero Go parameters. The existing
native/ejected matrix above now has fresh scoped acceptance at frozen45.

M5-S3 and M5-A's claims that their placement-probe reconciliation is not
implemented are also stale: the current fixtures already place the faulting
store beyond the checked-source boundary, and those fixtures passed here.
The matching implementation notes can describe these implemented and tested
mechanisms without changing SPEC or claiming a universal unsafe proof.

Compilation used the task's disk object directory and postbuild cache.
Test execution used fresh real home-directory temps to avoid workspace VCS
ancestry. The wrapper set one Go worker, GOGC=20, and a 512MiB soft heap
limit. The command harness constructs its own child environment; CPU
affinity restricted the script process and descendants to one CPU.
Both binaries had explicit four-minute test timeouts and five-minute outer
bounds. No test timed out, no selected test skipped, and no new mutation
probe or production attempt was made.

The queued source integrations, full Go regression, broad scripts, other
release configurations, and unresolved M6 default-application work remain
outside this scoped acceptance.
